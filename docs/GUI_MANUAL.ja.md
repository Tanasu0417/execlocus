# ExecLocus GUI 操作ガイド

ExecLocusは、同じ開発プロジェクトをWindowsとWSL2から使うときに「どのOS層で、どの実行ファイルが選ばれるか」を確認する読み取り専用ツールです。

## 何を防ぐためのツールか

- WSLで作業しているつもりでも、Windows版のNodeやCodexが優先される
- 依存関係、キャッシュ、設定、認証情報が想定と異なる側へ作られる
- 同じリポジトリでも、起動方法によってGit・Node・AIエージェントの挙動が変わる
- 不具合の原因がコードなのか、Windows／WSL境界なのかを判断できない

## 最短の使い方

1. Windowsアプリを、確認したいプロジェクトから起動します。
2. 「重視する使い方」を選びます。迷った場合は「迷ったらこれ」を使います。
3. 「WindowsとWSLを比較」を押します。
4. 「今回わかったこと」で、要修正・要確認の件数を確認します。
5. 「Win／WSL差分」で、異なる実行ファイルだけを確認します。
6. 「対応方法」で影響、推奨対応、確認コマンド、再診断手順を確認します。
7. 他の人へ相談するときは「安全に共有」からMarkdownをコピーします。

## 3つの診断基準

| 画面上の名称 | 内部名 | 選ぶ目安 |
|---|---|---|
| Windows共有優先 | `share-first` | Explorer、Windows側エディタ、Coworkなどから同じファイルを直接開きたい |
| 迷ったらこれ | `balanced` | 初回診断、または配置方針が決まっていない |
| WSL性能優先 | `linux-first` | Linux本番との一致、ビルド性能、ファイル監視を優先したい |

診断基準は、同じ観測結果を「問題」「注意」「意図した構成」のどれとして説明するかに影響します。環境自体を変更する設定ではありません。

## Windows／WSL自動比較の準備

Windowsアプリは、WSL内の無料ローカル補助バイナリを呼び出して両側を比較します。WSL側のExecLocusリポジトリで、初回だけ次を実行してください。

```bash
bash scripts/install-wsl-companion.sh
```

この操作はソースからExecLocusをビルドし、WSLのCargoバイナリディレクトリへ導入します。ホスト型AI、有料API、APIキーは使用しません。

## 画面の読み方

- `診断結果`: 現在のOS層、シェル、プロジェクト境界、AIエージェント、5ツールの選択を表示します。
- `Win／WSL差分`: Windows側とWSL側で異なる項目を先に表示します。「同じ項目も表示」で全項目を確認できます。
- `対応方法`: 検出ごとに、影響、推奨対応、確認コマンド、再診断方法を表示します。
- `安全に共有`: 識別情報を置換したHTMLプレビューを表示し、同じ内容をMarkdownとしてコピーします。

## 自動匿名化の範囲

共有用レポートを作る前に、ユーザー名、PC名、ホームディレクトリ、個人の絶対パスを安全なプレースホルダーへ置換します。診断画面はローカル確認用なので、実際のパスを表示する場合があります。

未加工のJSON、ターミナル出力、画面全体のスクリーンショットは自動匿名化の対象外です。そのまま公開しないでください。

## 現時点の制約

- Windowsアプリをどのプロジェクトに対して実行するかは、アプリを起動したディレクトリで決まります。フォルダ選択画面は今後の優先機能です。
- WSL内のaliasやfunctionを正確に含める診断は、そのシェルから試用スクリプトを起動した場合が最も確実です。
- 開発版exeは未署名です。一般配布用の署名・インストーラー・自動更新はまだ含みません。
