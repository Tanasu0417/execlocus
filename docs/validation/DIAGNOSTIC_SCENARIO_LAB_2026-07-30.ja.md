# ExecLocus 診断シナリオラボ

- 更新日: 2026-07-30
- 目的: 抽象的な環境情報ではなく、WSL開発で起こる症状を「発見・判断・修正・再検証」まで再現する

## 結論

診断価値を伝えるには、正常なPCを1回表示するだけでは不十分です。安全に隔離した失敗状態を用意し、ExecLocusによって原因候補と次の行動が短時間で分かることを、複数の再現可能なシナリオで示します。

実機データと合成データは画面上で明確に区別します。合成シナリオを実環境で検出した問題のように見せません。

## 安全ルール

- グローバルな `PATH`、シェルプロファイル、`.wslconfig`、WSLディストリビューションを変更しない。
- 一時ディレクトリと子プロセス内の環境変数だけで不一致を作る。
- ユーザー名、PC名、ホームディレクトリ、個人の絶対パスは合成値を使う。
- 実行前に作成物、実行コマンド、想定時間、削除方法を表示する。
- 外部API、ホスト型AI、有料クラウド、課金ランナーを使わない。
- `wsl --unregister`、実環境の更新、実環境の破壊を再現手段にしない。

## 1シナリオの画面契約

各シナリオは次の順序で表示します。

1. **症状**: 利用者が遭遇する現象を1文で示す。
2. **発見**: ExecLocusが観測した実行ファイル、OS層、PATH順位、配置を示す。
3. **影響**: このまま作業した場合に起こり得ることを、断定範囲を守って示す。
4. **最小修正**: 自動変更せず、最小の候補を1つ示す。
5. **再検証**: 同じ条件で再診断し、警告が消えたことを確認する。
6. **共有**: 匿名化対象のプレビュー後にMarkdownをコピーできる。

## 合格条件

- 初見の利用者が60秒以内に原因候補を説明できる。
- 表示内容から、変更前に確認すべきコマンドを選べる。
- before／afterで「何が直ったか」を説明できる。
- 合成シナリオと実機診断を取り違えない。
- 共有用出力に合成前の識別情報や秘密値が残らない。

## 実装順

1. 既存能力だけで成立する `LAB-03`、`LAB-04`、`LAB-07` を先に追加する。
2. Windows／WSLペア診断を使う `LAB-01` を追加する。
3. 前回正常状態の差分を実装し、`LAB-05` を追加する。
4. 上限付き性能・監視probeを設計し、`LAB-06` を追加する。
5. 利用者が期待するCI・本番条件を明示するターゲット契約を設計し、`LAB-02` を追加する。
