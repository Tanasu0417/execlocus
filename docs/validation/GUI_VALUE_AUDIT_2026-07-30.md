# ExecLocus GUI・製品価値監査（2026-07-30）

## 結論

ExecLocusの中心価値は、WindowsとWSLで「実際にどの実行ファイルが選ばれるか」を同じ形式で観測し、違いの影響、確認コマンド、再診断までを短時間で示すことです。

一般的なシステム情報表示だけでは、WSL2利用者が継続して使う理由になりません。次の問いに答えられることを合格条件とします。

1. 今いるのはWindowsかWSLか。
2. Git・Node・npm・Codex・Claude Codeは、どちら側の何が選ばれるか。
3. Windows側とWSL側で、意図しない違いがあるか。
4. その違いで何が起こり得るか。
5. 次に何を確認し、直した後にどう再検証するか。

## 必須機能になるための優先順位

### P0: 公開前に必要

- 診断対象フォルダを利用者が明示的に選べる。
- Windows／WSLペア診断を、手作業で2回実行せず完了できる。
- 期待する使い方と実測結果の不一致を、結論として先に示す。
- 選ばれた実行ファイル、由来、形式、候補、理由を追跡できる。
- 修正候補と確認コマンドを示し、再診断で改善を確認できる。
- 共有用出力から識別情報を置換し、画面上で確認してからコピーできる。

### P1: 継続利用につながる

- 前回診断との差分を保存し、環境更新による変化を検出する。
- チームの期待値をポリシーファイルとして保存し、逸脱を警告する。
- fnm・nvm・Voltaなど、バージョン管理ツール由来の選択根拠を説明する。
- Dev Containerやコンテナ内との境界も同じモデルで比較する。
- GitHub Issueへ貼れる再現情報を、匿名化済みMarkdownで作る。

### P2: 将来検討

- カワウソの状態アニメーション。
- WSL操作用のターミナル統合。
- Ollamaによるローカル説明補助。

P2は体験向上には役立ちますが、診断精度と問題解決時間を改善するP0/P1より先には実装しません。Ollamaは同梱サイズ、モデルライセンス、端末性能、更新・脆弱性管理を別途評価します。

## Windows／WSL自動比較の価値判定

比較画面は、単に値が違うことを示すだけでは不十分です。次を満たすときに価値があると判定します。

- 同じプロジェクトを両側から観測していることが分かる。
- OS境界として当然違う項目と、事故につながる違いを区別する。
- WSL側でWindows由来のPEや `/mnt/c` 上のツールが選ばれた場合に強調する。
- PATH、alias、functionなど、選択理由を表示する。
- 修正後に同じ条件で再比較できる。

## 利用者テストの合格条件

初見のWSL2利用者が、説明者なしで次を完了できることを確認します。

1. 30秒以内に製品の役割を説明できる。
2. 自分に合う利用目的を選べる。
3. 1回の操作でWindows／WSL比較を開始できる。
4. 60秒以内に、意図しない選択があるか判断できる。
5. 表示された確認コマンドと再診断方法を理解できる。
6. 共有前に何が匿名化されるか説明できる。

「情報が見えた」ではなく、「新しい問題を発見できた」「判断時間が短くなった」「修正後の確認に再利用したい」のいずれかを得られたかを最終評価に使います。

## 安全性と費用

- 診断は読み取り専用です。
- GUIはループバックアドレスだけで待ち受けます。
- Windows／WSL比較はローカルの `wsl.exe` とExecLocusだけを使用します。
- 外部API、ホスト型AI、有料クラウド、課金ランナーを使用しません。
- WSL補助バイナリの導入は無料ですが、利用者が明示的に実行します。
- 未加工JSONや端末出力は、共有用レポートとは別物として扱います。
